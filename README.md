# gcp-architect-blog

Reference GCP architecture and platform engineering blog — deep,
code-first posts backed by working Terraform, real command output, metrics, and
cost. Built with [Astro](https://astro.build), deployed to Firebase Hosting.

By **Koate Kpai**.

## Why this exists

Every post ships evidence: a companion Terraform example under `examples/<slug>/`
and captured proof under `public/evidence/<slug>/`. No slideware.


New posts include a readable result or architecture visual near the opening,
with a caption, alt text and a shareable LinkedIn version. Follow the
[post visual standard](AGENTS.md#post-visuals).

## Stack

- **Astro 5** (static output, MDX, Shiki highlighting, Mermaid diagrams
  pre-rendered to inline SVG at build time via Playwright/Chromium).
- **Single `posts` content collection** — no duplicated per-category trees.
- **7 pillars (A–G)**; the letter is derived from `category`, never stored.
- **3 cloud tracks (aws | gcp | azure | multi)**; a cloud is optional on a post and
  defaults to `gcp`. `/clouds/` filters by track; `multi` is the cross-cloud bridge.
- **Proof tiers**: `1` live run, `2` code proof, `3` reference.
- **Org gating**: topics needing a GCP organization carry `requiresOrg: true` and
  are scheduled last.

## Commands

```bash
npm install
npm run dev        # local dev server
npm run build      # static build to dist/
npm run preview    # preview the build
npm run new:post -- <category> <id> "<title>"
npm run score      # regenerate content-ops/scorecard.md from backlog.yaml
```

## Content model

Add posts at `src/content/posts/<category>/<NNN>-<slug>.mdx` with frontmatter:

```yaml
---
title: "…"
description: "80-200 chars"
category: "security-iam"   # one of the 7 pillars
cloud: "gcp"               # optional track: aws | gcp | azure | multi (default gcp)
tags: ["terraform", "iam"]
publishDate: 2026-10-07
draft: false
series: "keyless-ci"       # optional
seriesOrder: 1             # optional
impact: 5                  # scoring: (impact x demand x confidence) / effort
demand: 5
confidence: 5
effort: 2
proofTier: 2               # 1 | 2 | 3
requiresOrg: false
codeRepo: "https://github.com/…/examples/…"   # optional
---
```

Pillars (A–G) live in `src/data/categories.ts`.

### Editorial backlog

`content-ops/backlog.yaml` tracks `planned`, `published` and `merged` topics.
`npm run score` scores only planned topics and lists the other two separately, so
the scorecard never reports live work as unstarted. IDs must be unique within a
category; `npm run new:post` refuses to reuse an existing prefix.

### Proof tiers

| Tier | Meaning | Evidence |
|---|---|---|
| 1 | Live run | deploy, screenshots, metrics, cost, teardown |
| 2 | Code proof | `terraform apply` output, commands, diagrams |
| 3 | Reference | architecture + code + tradeoffs, no live run |

## Project layout

```
src/
  content.config.ts        # posts schema (Astro v5 glob loader)
  data/categories.ts       # 7 pillars + derived A-G letters
  content/posts/           # one collection, nested by pillar on disk
  layouts/                 # BaseLayout, PostLayout
  components/              # CategoryBadge, TagList, TableOfContents, Callout, PostCard
  pages/                   # index, posts, categories, tags, about, rss, 404
examples/<slug>/           # companion Terraform + workflows per post
public/evidence/<slug>/    # captured screenshots + metrics per post
content-ops/backlog.yaml   # editorial backlog (scored)
content-ops/scorecard.md   # generated by `npm run score`
```

## Deployment

Firebase Hosting. Set `site` in `astro.config.mjs` to your hosting URL, then:

```bash
npm run build
firebase deploy --only hosting
```

> Deploy pipeline, keyless CI, and infra-as-code: see `docs/firebase-setup.md`.
